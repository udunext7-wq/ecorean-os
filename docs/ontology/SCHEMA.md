# ECOREAN 온톨로지 스키마 v3.0

건축·인테리어 전 생애주기의 공정 연계 규칙. 견적·발주·공정표가 이 정의를 따른다.
**정의의 SSoT는 이 문서와 `sites/net/app/studio/ontology/rules.json` 이며, 변경은 마스터 DB 승인 절차(엔진 12)로만 한다.**

- 규모: 규칙 258건 · 노드 383개 (v2.0 규칙 170건 전량 승계)
- 근거: BOC `cost_items` 40개 대분류(670건) 체계 + 건축 표준 시공·법정 절차
- 뷰어: `/studio/ontology` (ACCESS PORTAL 암호 통과 필요, 조회 전용)

## 1. 노드 규칙

노드는 **작업 단위 하나**를 뜻한다. 자재·브랜드·수량은 노드가 아니다(그것은 BOC 마스터 DB 소관).

### 1.1 노드 유형

| 유형 | 뜻 | 형상 | 통과 실패 시 |
|---|---|---|---|
| `PROCESS` | 시공 공정 — 실제 작업 (자재·인력·공기 발생) | 구체 | 하자·재시공 |
| `CHECK` | 검사·시험 — 품질/안전 확인 | 다이아몬드 | **통과 전 후속 공정 금지** |
| `PERMIT` | 인허가·행정 — 법정 신고·승인 | 육각형 | **공사 중단·처분 대상** |

판정 기준(자동): 이름에 `허가/신고/승인/등재/필증/증명/신청/심의/계약/계획서` → `PERMIT`,
`검사/시험/확인/점검/감리/측량/계측/조사/검수/성적서/보고서` → `CHECK`, 그 외 `PROCESS`.

### 1.2 노드 속성

| 속성 | 규칙 |
|---|---|
| `name` | 명사형 공정명. 규격은 괄호로 (예: `석고보드 (9.5T or 12.5T)`). 동일 개념 중복 금지 |
| `phase` | 생애주기 1~12 (아래 표) |
| `domain` | `건축` / `인테리어` / `공통` — 단계에서 자동 도출 |
| `type` | `PROCESS` / `CHECK` / `PERMIT` |

### 1.3 생애주기 12단계

| # | 단계 | 영역 | 포함 |
|---|---|---|---|
| 1 | 기획·인허가 | 공통 | 설계·실측·허가·신고·감리계약 |
| 2 | 해체·철거 | 공통 | 철거·석면·폐기물·보양·가설 |
| 3 | 지반·토공·기초 | 건축 | 지반조사·터파기·흙막이·기초 |
| 4 | 구조 골조 | 건축 | 배근·거푸집·타설·철골·조적 |
| 5 | 외피·지붕·외장 | 건축 | 지붕방수·외단열·외장재·커튼월 |
| 6 | 창호·개구부 | 공통 | 창호·새시·도어·발코니 확장 |

| 8 | 목공·경량 | 인테리어 | 경량틀·석고·가벽·천장 조작 |
| 9 | 방수·습식·타일 | 공통 | 방수·미장·타일·줄눈 |
| 10 | 마감 | 인테리어 | 도장·도배·바닥재·필름 |
| 11 | 설치 | 인테리어 | 가구·주방·욕실·조명·스마트홈 |
| 12 | 준공·검사·인도 | 공통 | 사용승인·완공검사·청소·하자 |

## 2. 엣지 규칙

엣지는 **한 공정이 다른 공정을 불러오는 관계**다. 방향은 항상 `triggerProcess → autoLinkProcess`(원인 → 결과).

### 2.1 관계 유형

| 유형 | 뜻 | 견적 처리 |
|---|---|---|
| `필수` | 반드시 함께 수행 — 누락 시 하자·법규 위반 | **자동 포함** (제외하려면 사유 기록) |
| `권장` | 품질·내구를 위해 권장 | 기본 포함 후 협의로 제외 가능 |
| `선택` | 고객 결정 항목 | 미포함, 옵션 제시 |
| `제안` | 현장 상황에 따라 제안 | 실측 후 판단 |
| `조건` | 조건 충족 시에만 발생 | `condition` 충족 시 포함 |
| `선행` | 순서 관계 — 역순 시 재작업 | 수량 없음, 공정표에만 반영 |
| `대체` | 동일 부위 택1 — 상호 배타 | **동시 견적 금지** |

### 2.2 엣지 속성

| 속성 | 규칙 |
|---|---|
| `condition` | `항상` 또는 발생 요건 명시 (예: `굴착 심도 2m 이상`) |
| `quantityCalc` | 산출 근거를 문장으로 (예: `타일면적 × 1.1`). `선행`·`대체`는 `-` |
| `note` | 실무 주의사항 — 왜 필요한지, 빠뜨리면 무엇이 터지는지 |

### 2.3 무결성 규칙 (생성 시 자동 검증)

1. **자기참조 금지** — `trigger === autoLink` 불가
2. **중복 금지** — 동일 `(출발, 도착, 유형)` 조합 1회만
3. **순환 금지** — `대체`를 제외한 관계에 사이클 불가 (선행 순환은 공정 자체가 불가능)
4. **수량 명시** — `선행`·`대체` 외 모든 엣지는 `quantityCalc` 필수
5. **조건 명시** — `조건` 유형은 `condition`이 `항상`이면 안 됨

> v3.0 검증 결과: **오류 0건** (자기참조 0 · 중복 0 · 순환 0)

## 3. 활용

| 소비처 | 사용 방식 |
|---|---|
| 견적 (EstimateEngine) | `필수`·`조건` 연계를 자동 포함해 **누락 방지**, `대체`는 택1 강제 |
| 공정표 (ScheduleEngine) | `선행` 관계로 순서 검증, 역순 배치 경고 |
| 발주 (procurement) | 연쇄 체인으로 동반 자재 산출 |
| AI 스튜디오 | 무드보드 자재 태그 ↔ 공정 매칭의 기준 |

## 4. 변경 절차

1. 규칙 초안 작성 → `rules.json` 갱신 (생성기: `scratchpad/build_ontology_v3.py` 패턴)
2. 자동 검증 통과 (§2.3)
3. **대표 검토 승인** — 현행 v3.0은 `초안 · 검토 대기` 상태
4. 승인 후 버전 증가 및 마스터 DB 반영 (엔진 12 MasterDBUpdateRequest)
