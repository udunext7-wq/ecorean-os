## 결정 #1 — 기술 스택: Electron + HTML 모듈

### 결정일
2026-04 초 (v1.0~v2.0 사이)

### 결정 내용
**최종: Electron + HTML 모듈 방식 채택**

### 경위 (시행착오)
```
시도 1: 단일 HTML 파일
  → 코드가 길어지면서 관리 불가
  → 탭 전환 시 전체 리렌더링

시도 2: 마이크로 프론트엔드 (iframe)
  → file:// 프로토콜에서 iframe 보안 제한 발생
  → cross-origin 정책 → IPC 통신 불가

시도 3: 단일 HTML 복귀
  → 7,000줄 돌파 → 버그 급증

최종: Electron BrowserView 탭 격리
  → 각 탭 = 독립 HTML 모듈
  → IPC로 상태 공유
  → 보안 제한 없음
```

### 결정 이유
- `file://` 환경에서 iframe cross-origin 제한 회피 불가
- BrowserView는 Electron이 직접 관리 → 보안 제한 없음
- 각 모듈 독립 → 한 탭 오류가 다른 탭에 영향 없음
- 안정성 + 관리성 우선

### 교훈
> iframe + file:// 조합은 쓰지 않는다. Electron에서 탭 격리는 BrowserView만이 답이다.

## 결정 #2 — 블록 시스템 도입

### 결정일
2026-04-27 (v5.0)

### 결정 내용
**파일 크기 기준 블록 분할 + 4계층 아키텍처 도입**

### 근거 (실증 데이터)
```
관찰:
  단일 파일 1,000줄: 버그 거의 없음
  단일 파일 3,000줄: 버그 산발적 발생
  단일 파일 7,500줄: 버그 발생률 급증 (임계점)

결론:
  7,500줄 = 사람이 한 파일 전체를 머릿속에 담을 수 없는 한계
```

### 블록 크기 기준
```
정상:  1,500 ~ 3,000줄 (목표 구간)
경고:  3,001 ~ 5,000줄 (분할 계획 수립)
위험:  5,001 ~ 7,500줄 (분할 준비)
금지:  7,501줄+         (즉시 분할)
```

### 확장 방식: 행렬 확장 → 상위 적층
```
행렬 확장 (분할):
  7,500줄 도달 시 4분할
  의미 단위로 나눔
  인터페이스로만 연결

상위 적층 (조합):
  조합기는 단순 호출만
  블록은 독립 작동
  Layer N+1 = Layer N의 조합
```

### 기대 효과
- 100배 확장 가능 구조 (블록 추가만으로 기능 확장)
- 버그 격리 (한 블록 오류 = 해당 블록만 영향)
- 테스트 용이 (블록 단위 독립 테스트)
- AI 페어 프로그래밍 적합 (블록 단위 생성/수정)

## 결정 #3 — 메타 온톨로지

### 결정일
2026-04-27 (v5.0)

### 결정 내용
**시스템 자체를 온톨로지로 표현 — 도메인 + 시스템 통합 그래프**

### 발상의 기원
> 대표님 발상: "블록이 노드고, 연결이 엣지면, 우리 시스템 자체가 온톨로지 아닌가?"

### 의미
```
기존:
  인테리어 온톨로지 (공정/자재/브랜드/규칙) → Neo4j

v5.0 추가:
  시스템 온톨로지 (블록/레이어/인터페이스/의존성) → Neo4j

통합 결과:
  하나의 Neo4j 그래프에서
  "estimate.html이 사용하는 DB 테이블?"
  "FinanceEngine 변경 시 영향 블록?"
  같은 질의가 Cypher 한 줄로 가능
```

### AI 페어 프로그래밍과의 연결
```
Claude API + Neo4j:
  자연어 질의 → Cypher 변환 → 결과 반환
  시스템이 자기 자신을 알고 있음
  AI가 시스템 구조를 이해하고 코드 생성
```

### 결정 이유
- 시스템 복잡도 증가 시 구조 파악이 병목
- Neo4j로 시스템 구조 자체를 질의 가능하면 이 병목 제거
- 추가 비용 없음 (Neo4j는 어차피 사용)

## 결정 #8 — 대표님 핵심 가치관

### 기록일
2026-04-27

### 이 프로젝트를 관통하는 가치관

**① 사람이 아닌 시스템이 판단한다**
> 사람의 경험과 감으로 운영하면 성장에 한계가 있다.
> 시스템이 데이터를 보고 판단하면 100명이 일해도 품질이 일정하다.

**② 데이터가 시스템을 성장시킨다**
> 현장 데이터가 쌓일수록 견적 정확도, 온톨로지, AI가 자동으로 성장한다.
> 우리가 일할수록 시스템이 강해진다.

**③ 100배 확장 가능 구조**
> 지금 1명이 쓰는 시스템이 100명이 써도 무너지지 않아야 한다.
> 블록 아키텍처, Neo4j, TypeScript 인터페이스가 이를 보장한다.

**④ 일을 두 번 하지 않는다**
> 한번 설계한 것은 재사용한다.
> 한번 입력한 데이터는 전체에 반영된다.
> 한번 정한 결정은 이 문서에 기록하여 다시 고민하지 않는다.

**⑤ 미래지향적 설계**
> 지금 당장은 1명이 쓰더라도, 프랜차이즈 확장을 설계에 반영한다.
> Phase 0 코드가 Phase 4의 기반이 된다.

**⑥ 안정성 + 완성도**
> 빠른 것보다 올바른 것.
> 버그 있는 배포보다 늦은 배포.
> 절반짜리 기능 10개보다 완전한 기능 3개.

**⑦ 깊이 있는 사고**
> 표면적 해결책보다 근본 원인을 찾는다.
> 단기 이익보다 장기 구조를 선택한다.
> "왜?"를 5번 물어본다.
